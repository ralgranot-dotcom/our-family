## 2. ארכיטקטורה

```
טלפונים / דפדפן  (PWA — HTML/JS, עברית RTL)
        │  HTTPS
        ▼
GitHub Pages  ← קבצי האפליקציה (index.html, app.js, sw.js …)
        │
        ▼
Supabase (פרויקט ddytetgcdygmufitgxeg, פרנקפורט)
  ├─ Auth            — התחברות במייל או בטלפון + סיסמה
  ├─ Postgres + RLS  — כל הנתונים; הרשאות נאכפות בשרת
  ├─ Realtime        — עדכון מיידי בכל המכשירים
  ├─ Storage         — תמונות פרופיל (דלי פרטי fam-media)
  ├─ Edge Function   — family-api: הרשמה, התראות, איפוס סיסמה, מחיקת חשבון, תזמון
  └─ pg_cron         — כל 10 דקות: תזכורות, ימי הולדת, התראות שנדחו
        │
        ▼
Web Push (VAPID) → התראות לטלפון, גם כשהאפליקציה סגורה
```

- **הפרדה מחוד החנית:** כל הטבלאות של האפליקציה מתחילות ב-`fam_`. חשבונות ההתחברות של האפליקציה המשפחתית נוצרים בכתובת פנימית (`…@family-app.invalid`), ולכן לא מתנגשים בחשבונות של מערכות אחרות ואין להם גישה לתקצירים.
- **בלי סודות בקוד:** בצד הלקוח יש רק את המפתח הציבורי (anon). המפתח הסודי ומפתח ה-VAPID הפרטי שמורים רק בשרת.

## 3. מבנה מסד הנתונים

| טבלה | תפקיד |
|---|---|
| `fam_profiles` | פרופיל אישי: שם, כינוי, תמונה, יום הולדת, טלפון, מייל, הגדרות |
| `fam_families` | קבוצות משפחתיות |
| `fam_members` | שיוך משתמש↔משפחה, תפקיד (`owner` / `admin` / `member` / `junior`) ומצב (`active` / `pending`) |
| `fam_invites` | קודי הזמנה: תוקף, מספר שימושים מרבי, האם נדרש אישור |
| `fam_events` | אירועים |
| `fam_event_invitees` | מוזמנים לאירוע שאינו "כל המשפחה" |
| `fam_rsvps` | אישורי הגעה. מפתח ראשי (אירוע, משתמש) מונע כפילות |
| `fam_notifications` | התראות בתוך האפליקציה + מצב שליחת Push |
| `fam_push_subs` | מכשירים רשומים להתראות |
| `fam_audit` | יומן פעולות ניהול |
| `fam_bug_reports` | דיווחי תקלות מהאפליקציה |
| `fam_private_config` | הגדרות פנימיות לשרת. חסומה לחלוטין ללקוח |

קבצי ה-SQL נמצאים בתיקייה `supabase/`. קוד פונקציית השרת נמצא ב-`supabase/functions/family-api/`.

## 4. הרשאות

- כל משתמש רואה רק את המשפחות שהוא חבר פעיל בהן, ובתוכן רק אירועים שהוזמן אליהם.
- מי שממתין לאישור לא רואה שום אירוע.
- **מנהל ראשי / מנהל:** מזמינים, מאשרים, משנים הרשאות, מסירים משתתפים ומאפסים סיסמאות.
- **משתתף:** יוצר אירועים ומאשר הגעה.
- **משתתף צעיר:** צופה ומאשר הגעה בלבד.
- אף משתמש לא יכול לשנות את אישור ההגעה של מישהו אחר, לערוך אירוע של אחר (אלא אם הוא מנהל) או להעלות לעצמו הרשאות.
- כל הכללים האלה נבדקו מול השרת האמיתי. ראו "בדיקות" בהמשך.

## 5. ניהול גרסאות

שיטת מספור: `X.Y.Z`.
- `Z`: תיקוני תקלות.
- `Y`: יכולות חדשות.
- `X`: שדרוג משמעותי.

**בכל עדכון חובה לעדכן את המספר בכל המקומות האלה:**
1. `config.js`, בשדה `version`.
2. `sw.js`, בשורה `VERSION` ובשני ה-`?v=`.
3. `index.html`, בשני ה-`?v=`.
4. `version.json`, בשדה `version` ובהוספת רשימת "מה חדש".

השדה `min_supported` ב-`version.json` מגדיר את הגרסה המינימלית שנתמכת. גרסה ישנה ממנו תציג למשתמש חובת עדכון.
העדכון מחליף רק את קבצי האפליקציה. כל נתוני המשתמשים שמורים בשרת ונשמרים בעדכון.

## 6. גיבוי ושחזור

- כל הנתונים נשמרים ב-Supabase, שמבצע גיבוי יומי אוטומטי.
- כל משתמש יכול לייצא את המידע שלו לקובץ: הגדרות ← "ייצוא המידע שלי".
- מחיקת חשבון מוחקת רק את נתוני האפליקציה המשפחתית של אותו משתמש.

## 7. בדיקות שבוצעו בפועל (גרסה 1.0.0)

- הרשמה במייל ובטלפון, דרך פונקציית השרת האמיתית.
- 25 בדיקות הרשאה מול מסד הנתונים האמיתי. בין השאר נבדק ש:
  - זר לא רואה אירועים, פרופילים או תקצירים.
  - משתתף ממתין לא רואה אירועים.
  - משתתף לא עורך אירוע של אחר.
  - אי אפשר לאשר הגעה בשם מישהו אחר.
  - אי אפשר להעלות לעצמך הרשאות.
  - קוד הזמנה שגוי נדחה.
- תזמון התזכורות. נבדק גם שסיסמה שגויה לתזמון נחסמת.
- 46 בדיקות ממשק אוטומטיות על כל המסכים, מול שרת מדומה: כניסה, אישור הגעה, נלווים, תזכורת, הודעה, עריכה, ביטול, אירוע חדש, זיהוי חפיפה, לוח שנה, הזמנה, אישור מצטרף, הרשאות, התראות, הגדרות, מצב כהה, בדיקת תקינות, אודות, דיווח תקלה, עבודה בלי חיבור ומצב תצוגה פשוטה.
- התאמה מלאה בין האפליקציה לשרת בזיהוי משתמש לפי מייל או טלפון, כולל טלפון בפורמט +972.
- בדיקת תחביר לכל הקבצים, ובדיקה שכל התבניות במסכים סגורות כראוי.

**לא נבדק על מכשיר אייפון פיזי.** ההתנהגות באייפון מבוססת על התמיכה של Safari ב-PWA (iOS 16.4 ומעלה).
